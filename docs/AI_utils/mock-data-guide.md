# 발표자용 가데이터 설계·활용 설명표

이 문서는 개발에 참여하지 않은 발표자가 가데이터의 생성 기준과 사용 이유를 설명할 수 있도록 작성했습니다. 생성 코드와 저장소 CSV를 확인한 **2026-10-28 기준**입니다. 실제 운영 DB의 현재 행 수를 새로 조회한 결과는 아닙니다.

**발표에서 먼저 말할 핵심:** 실제 여행자의 영수증을 수집한 데이터가 아니라, 여행 중 발생할 법한 구매를 규칙과 확률로 생성한 시연용 데이터입니다. 목적은 **내 영수증 기록이 다른 여행자의 가격 비교와 소비 분석에 연결되는 흐름을 검증하는 것**입니다. 확률과 가격 차이는 시연을 위한 설계값이며, 실제 여행자 조사나 시장조사에서 얻은 비율이 아닙니다.

## 1. 전체 구조와 규모

| 자료        | 생성 규모 | 쉽게 설명하면                                            | 이 자료가 필요한 이유                                                                    |
| ----------- | --------: | -------------------------------------------------------- | ---------------------------------------------------------------------------------------- |
| 가상 여행자 |     300명 | 서로 다른 구매 기록을 가진 익명 여행자 300개 계정에 해당 | 한 사람이 반복 구매한 기록과 여러 여행자의 기록을 구분하고, 여행별 소비 비교를 하기 위해 |
| 여행        |     300건 | 여행자마다 도쿄 여행 한 번                               | 예산·기간·통화가 있어야 소비 비중과 하루 지출을 계산할 수 있기 때문                      |
| 영수증      |   8,152건 | 여행 중 식사·쇼핑·숙박·교통 등에 쓴 구매 기록            | 가계부 합계, 매장 위치, 구매일, 공유 여부를 연결하기 위해                                |
| 영수증 품목 |  17,262건 | 영수증에 적힌 상품·서비스의 줄별 내역                    | 총 결제액만으로는 같은 상품의 매장별 단가를 비교할 수 없기 때문                          |
| 매장        |     171곳 | 영수증 속 가상 매장 171곳. 별도의 매장 테이블은 없음     | 같은 상품을 여러 곳에서 비교하고, 거리와 가격의 차이를 보여 주기 위해                    |
| 상품 종류   |     150종 | 150종의 상품·서비스가 여러 영수증에 반복 등장            | 반복 구매가 있어야 구매 횟수와 동일 상품의 가격 차이를 계산할 수 있기 때문               |

**300명은 통계적으로 최적인 표본 수를 계산한 결과가 아닙니다.** 공유 여부·거리·여행 종료 여부로 기록을 걸러도 여러 비교 사례가 남도록 잡은 개발용 규모입니다. 영수증 8,152건과 품목 17,262건은 300명의 여행 행동을 생성한 **결과 수량**입니다. 이 두 숫자를 먼저 정해 놓고 행을 채운 것은 아닙니다.

DB는 여행자(`devices`) → 여행(`trips`) → 영수증(`receipts`) → 품목(`receipt_items`)의 네 테이블로 연결됩니다. 매장 정보는 영수증에, 상품 정보는 품목에 함께 저장합니다.

| PAGE 1 Claude 분석             | 서버가 계산한 예산·기간·지출·집단 비교 수치 전달                                                                       | 그 수치로 분석 문장 작성. 근거에 없는 숫자가 나오면 규칙 기반 문장 사용         | “비교 숫자는 서버가 계산하고, AI는 그 숫자를 설명합니다.”                                                                                                           |

현재 PAGE 2 API와 화면은 **음식·쇼핑·교통·숙박·관광·기타의 6개 가계부 카테고리**를 사용합니다. 생성 CSV에는 예전 둘러보기용 8개 세부 분류(`browse_category`)도 남아 있지만, 현재 조회 필터는 `ledger_category`입니다. 이전 문서의 ‘8개 카테고리’ 설명을 현재 화면 설명에 그대로 사용하지 마세요.

PAGE 1의 ‘소비 인사이트’와 도넛 차트의 ‘다른 여행자의 소비와 비교하기’도 구분해야 합니다. **소비 인사이트는 DB 집계 기준**, 기존 도넛 비교 표는 **고정 시연 비율**을 사용합니다.

## 6. 30초 설명문

> 저희는 도쿄를 여행하는 가상 여행자 300명의 기록을 만들었습니다. 각 여행의 일정에 따라 식사·숙박·쇼핑을 발생시켜 영수증 8천여 건을 생성했고, 같은 상품이 여러 매장에서 반복 구매되도록 가격과 거리를 다르게 설정했습니다. 공유에 동의한 주변 기록으로 가격을 비교하고, 서버가 계산한 상위 후보 중에서 AI가 예산에 맞는 선택과 이유를 제안합니다. 이 데이터는 실제 여행 통계나 시장 가격을 주장하기 위한 자료가 아니라, 영수증이 다른 여행자의 합리적인 선택으로 연결되는 흐름을 보여 주는 시연 자료입니다.
