# 시연용 가데이터 (CSV)

`travel_won`의 4개 테이블([docs/db-design.md](../docs/db-design.md))에 맞춘 가데이터입니다. **2026-10-28에 `travel_won`에 적재했습니다**(아래 [적재 기록](#적재-기록)).

- 만든 스크립트: [scripts/sample-data.mjs](../scripts/sample-data.mjs). `npm run sample-data`로 다시 만듭니다. 시드가 고정되어 있어 항상 같은 파일이 나옵니다.
- **모두 가상입니다.** 매장명, 주소, 가격, 여행자는 지어낸 것입니다. 상품명만 검색 시연을 위해 실제 브랜드(DORITOS, 하다라보 등)를 쓰고, 가격은 실제와 다를 수 있습니다. 주소에는 `(가상 주소 NN)`을 붙였습니다.

## 시나리오

한국인 여행자 300명이 2026년 8–10월에 도쿄를 2–6박 여행하며 쓴 영수증입니다. 시연 위치는 신주쿠역(`35.6896, 139.7006`)입니다.

- **매장 171곳:** 신주쿠역 반경 3km 안 130곳(니시신주쿠·가부키초·신오쿠보·요요기·하라주쿠 등), 반경 밖 41곳(시부야·이케부쿠로·긴자·아사쿠사)
- **여행자 행동:** 75%는 신주쿠 근처에 묵습니다. 하루에 식사 2–3번, 편의점, 쇼핑(화장품·의류·기념품), 명소·액티비티·웰니스, 교통 영수증을 확률에 따라 남깁니다. 숙박은 체크인 날 한 번에 결제합니다.
- **인기 차이:** 상품마다 가중치를 둬 많이 팔리는 상품(규동, 도리토스 나초치즈, 하다라보 로션 등)이 생기도록 했습니다. 같은 상품도 매장마다 가격이 0.92–1.08배로 다르고(할인점은 약 0.85배), 가끔 10% 할인가로 삽니다.
- **공유 동의:** 여행자의 88%가 가격 공유에 동의합니다. 그중 약 5%의 영수증은 공유하지 않습니다. 교통(택시·교통카드 충전·리무진버스) 영수증은 매장 위치가 없어 공유하지 않습니다.

## 형식

- UTF-8, 첫 줄은 DB 열 이름, 쉼표 구분. 쉼표·따옴표가 들어간 값은 큰따옴표로 감쌉니다.
- **빈 칸 = NULL.** 빈 칸은 NULL을 허용하는 열(`latitude`, `longitude`, `browse_category`)에만 있습니다. NOT NULL 문자열 열에는 빈 문자열이 없습니다.
- 참·거짓은 `1`·`0`, 날짜는 `YYYY-MM-DD`, 시각은 `YYYY-MM-DD HH:MM:SS.ffffff`(일본·한국 시각), 환율은 소수 4자리입니다.
- `normalized_name`은 서버의 정규화 규칙(`LedgerService.normalize`)으로 `raw_name`을 바꾼 값이며, 150종 모두 서버 결과와 같은지 확인했습니다.
- `token_hash`는 공백이 들어간 문구의 해시입니다. 앱 토큰 형식과 맞지 않으므로, 누구도 가데이터 기기로 로그인하거나 가데이터를 고칠 수 없습니다.

## 다시 넣거나 지울 때 주의할 점

- `id`를 1부터 직접 정해 두었습니다. **빈 테이블에 넣어야** 하고, 순서는 `devices` → `trips` → `receipts` → `receipt_items`입니다. 넣은 뒤에는 앱이 새로 만드는 행이 이어서 번호를 받습니다.
- MySQL `LOAD DATA`는 빈 칸을 NULL이 아니라 `''`나 `0`으로 넣습니다. 이 방법을 쓰면 NULL 허용 열에 `NULLIF(@열, '')`를 써야 합니다.
- 서버는 전체 영수증이 30,000건을 넘으면 새 저장을 막습니다. 가데이터는 8,152건이라 여유가 있습니다.
- 지울 때는 `DELETE FROM devices WHERE is_sample = TRUE;` 한 번이면 여행·영수증·품목까지 함께 지워집니다(ON DELETE CASCADE).
